# PageSpeed Audit & Fixes for bit-site

## Problem Summary

PageSpeed Insights report shows no lab data (page too new / not enough CrUX data), but code review reveals several concrete performance and correctness issues that would impact scores once data is available. The site is already very lightweight (Astro static, Tailwind, no raster images), but several issues drag down Performance, SEO, and Best Practices scores.

---

## Issues Found (Priority Order)

### 1. CRITICAL — JSON-LD schema is broken (SEO / Best Practices)
**File:** `src/layouts/Layout.astro:63`

```astro
<script type="application/ld+json" is:inline>{JSON.stringify(jsonLd)}</script>
```

`is:inline` prevents Astro from evaluating template expressions. The built HTML literally contains `{JSON.stringify(jsonLd)}` as text — search engines and AI crawlers see this as garbage, not structured data.

**Fix:** Replace with `set:html` directive:
```astro
<script type="application/ld+json" set:html={JSON.stringify(jsonLd)} />
```

### 2. CRITICAL — Schema URLs point to wrong domain (SEO)
**Files:** `src/layouts/Layout.astro:35-36`, `src/pages/index.astro:26-31`

The `defaultSchema` and `index.astro` schema use `https://cybernattor.github.io` as the site URL and logo URL. The actual domain is `https://bit-tecnologies.pages.dev`.

**Fix:** Update all schema URLs to use `https://bit-tecnologies.pages.dev`.

### 3. HIGH — Broken SearchAction in schema (Best Practices)
**File:** `src/pages/index.astro:29-32`

```json
"potentialAction": {
  "@type": "SearchAction",
  "target": "https://cybernattor.github.io/search?q={search_term_string}"
}
```

There is no `/search` endpoint on this static site. This will cause a Rich Results error in Google Search Console.

**Fix:** Remove the `potentialAction` from the schema.

### 4. HIGH — Google Fonts render-blocking (Performance)
**File:** `src/layouts/Layout.astro:90-95`

Two link tags load the same Google Fonts URL — once as `preload` (as="style") and once as `stylesheet`. The `preload as="style"` is ineffective (browsers treat style preloads as render-blocking anyway). This creates redundant network requests and blocks rendering.

**Fix options (pick one):**
- **Option A (recommended):** Self-host fonts — download Manrope, Sora, IBM Plex Mono woff2 files into `public/fonts/`, use `@font-face` with `font-display: swap`. Eliminates external requests entirely.
- **Option B (quick):** Remove the `preload` tag, keep only the `stylesheet` tag. Add `media="print" onload="this.media='all'"` pattern for non-blocking load.

### 5. MEDIUM — Render-blocking inline script in `<head>` (Performance)
**File:** `src/layouts/Layout.astro:102-142`

The dark mode FOUC-prevention script is 40+ lines of blocking JS in `<head>`. It must run early, but can be made smaller.

**Fix:** Replace with the industry-standard 1-line pattern:
```html
<script is:inline>
  (function(){var t=localStorage.getItem('color-theme');if(t==='dark'||(!t&&matchMedia('(prefers-color-scheme:dark)').matches))document.documentElement.classList.add('dark')})();
</script>
```
This is ~200 bytes vs the current ~1.5KB, and handles the same logic. View Transition handlers can stay as separate module scripts.

### 6. MEDIUM — Incorrect DNS prefetch (Best Practices)
**File:** `src/layouts/Layout.astro:97`

```html
<link rel="dns-prefetch" href="https://cybernattor.github.io" />
```

No resources are loaded from `cybernattor.github.io`. This is a wasted DNS lookup.

**Fix:** Remove the line, or replace with `fonts.googleapis.com` / `fonts.gstatic.com` if not self-hosting fonts.

### 7. LOW — Duplicate LanguagePicker component (Code quality)
**Files:** `src/components/DynamicLanguagePicker.astro`, `src/components/LanguagePicker.astro`

Both exist. `Header.astro` uses `DynamicLanguagePicker`. `LanguagePicker` appears unused.

**Fix:** Remove `LanguagePicker.astro` if confirmed unused.

### 8. LOW — Large inline script in DynamicLanguagePicker (Performance)
**File:** `src/components/DynamicLanguagePicker.astro:52-143`

This component's `<script>` is inlined into every page's HTML (because Header is included everywhere). It's ~90 lines of JS.

**Fix:** Move the script to a separate `.ts` file and import it, so Vite can bundle and tree-shake it. Only needed on pages with the language picker.
